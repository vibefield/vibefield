What VibeField adds

puppeteer manages one agent run. rosetta indexes one device's agent history. Neither knows the other exists, and neither knows what a PTY, a device or a person is. VibeField adds the three things that make them a product: custody — every agent process is born in a PTY on this device's floor, inside field-native, which outlives the daemon that asked for it; composition and policy — fieldd joins the two runtimes to the floor, mints the tickets, enforces the scopes and the locality column, brokers consent, and writes the records; and presentation — the Godview deck, the canvas and the phone, none of which has ever parsed a vendor's format.

The ownership law those three sentences derive from is not restated here. It is stated once, in the umbrella, and this page assumes it. Both siblings enter as pinned sibling checkouts rather than published packages (siblings.lock.json, pnpm-workspace.yaml's fenced block), so an upgrade is a deliberate event and never a resolution.

Revisions. Everything marked Built on this page was read at vibe-field b7ebb444, puppeteer 2f5ce002 and rosetta e8d907ab. Where a claim is Designed or Owed it names the document or the roadmap row it comes from, and nothing intended is written in the present tense.

Process and plane diagram

Four processes per logged-in user, plus the vendor's own CLI. The two daemons are a pair with a lifetime rule — field-native outlives fieldd outlives the shell — and every arrow below is labelled with the channel it rides, because which channel a fact travels on is the whole of EL2.

The lifetime rule is a UX constraint, not a slogan. A managed session survives a fieldd restart because the PTY belongs to the floor and the run's claim is on disk — the next boot re-attaches at the run's next runtime epoch. It does not survive a field-native restart, so the session-persistence ceiling is daemon lifetime and the product says so rather than promising more.

Honest module notes

Two files in this list are piles rather than modules, and saying so is part of governing them.

agent-runtime.ts holds four concerns

createProfileStore (puppeteer's registry in fieldd's custody), DistributionRecordStore (the machine scope under the root lock), AgentRuntimeService (the runtime, the fold, personas, sessions, distribution) and the reconcile. The service class alone spans lines 447–2,590 and carries five in-memory maps, four timers and three entry kinds (ManagedEntry, PendingEntry, ExitedEntry).

Owed

daemon.ts registers every door inline

108 registrations in one file — 96 api.register and 12 api.registerSubscription — of which 23 are the agent plane's. The handlers are thin, but the file is 3,937 lines and a door's contract, its audit wrapper and its service call are read three screens apart.

Owed
The refactor slate is owed, not designed. Assessed 2026-09-22: split agent-runtime.ts by domain (the profile store, the distribution record, the fold, the re-attach) and lift daemon.ts's registrations into per-domain door modules. Nothing is ruled and no decision id exists yet, so this page names the shape of the debt and no more.

The floor's agent cell

A cell is a separate field-terminal-host process that runs ghosttea's terminal service for one workload class. Since TC-S2 the terminal unit inside field-native embeds no terminal service of its own: it supervises cells, mints their tokens and grant keys, publishes a revisioned route snapshot, and pumps the inventory it publishes to fieldd. The agent class gets its own cell, so an agent that floods its PTY cannot take down the panes a person is typing in.

The cell binary

Resolved beside the floor, or from FIELD_NATIVE_CELL_BIN. A class with no cell binary is a dead end that reports degraded with its reason, never a silent absence.

Two sockets per cell

A control socket (create, terminate, automate, config) and a frame socket (the bytes). fieldd speaks only the first. The second is what a ticket points a renderer at.

Custody admission

A machine-wide flock'd ledger shares one PTY budget across every user-pair on the machine, and kernel refusal stays the final authority. fieldd's own TERMINAL_SESSION_CAP refuses a spawn before the floor is asked.

Scrollback by class

2 MiB for an agent, 10 MiB for an interactive pane (TERMINAL_SCROLLBACK_CLASS_BYTES) — a byte cap, not a row cap, enforced at the native create seam.

Agent panes persist

The class is keep-until-explicit-close, not keep-until-exit: an agent that finishes leaves a pane with its final screen and a resume verb on it.

Why puppeteer never sees a PTY

puppeteer's host capability is two methods — spawnTerminal(spec) → {runtimeSessionId} and automateTerminal(id, operation). fieldd implements both over TerminalService, so what the adapter receives back is an opaque id for a terminal it cannot address, on a device it has no word for. The adapter owns the whole launch recipe (command, argv, hooks, its own environment variables); the host composes the environment policy, finds a cell and execs.

EL7 at the seam

The environment is fieldd's composition, not the adapter's and not puppeteer's. buildAgentEnvironment is a policy layer fieldd calls from inside its own spawnTerminal; the adapter's spec.env is a set of asks, not a grant; and the EL7 strip is fieldd's duty, because fieldd is the only party that knows what a daemon secret looks like. An agent PTY is born with a clean environment: a fixed passthrough allow-list from the daemon's own environment (fifteen POSIX keys, plus fifteen more folded by case on win32), then puppeteer's own policy for what a vendor TUI needs, then the adapter's spec.env layered last among the allowed. The strip runs after all three — every FIELD_* and FIELDD_* key is removed from the composed result — so nothing an adapter asked for can smuggle a daemon secret class through. The order is the point: a strip that ran before the merge would be defeated by the merge.

An agent cell PTY is also the re-attach's trust boundary. A session record is only acted on when its HMAC verifies against this user root's key and the PTY it names is one the floor still lists as an agent-cell session. A same-uid adversary dropping a file into agents/sessions/ cannot point fieldd at a terminal it never spawned.
The floor's refusal would otherwise be lost. When spawnTerminal throws, puppeteer folds it into a flat session failure — AGENT_SESSION_CREATE_FAILED, with the generic text agent session creation failed: <agent> (packages/runtime/src/runtime.ts). That code says a session did not start and nothing about why. So agent-host.ts keeps the floor's own typed error in lastRefusal(), cleared by the next attempt, and the door answers with that instead: the session cap, a missing executable, or UNAVAILABLE {service: "agents", state: "no-terminal-host"}. A host that did not keep it would leave a person reading one sentence for every possible cause.

The mirror and the fold

The fold is fieldd's single projection of "what agents exist and what they are doing", assembled from three inputs and published as whole snapshots.

puppeteer's monitor projection

runtime.onMonitorState, onMonitorRemoved and onMonitorNotification, coalesced upstream at the same 16 ms the fold itself ticks at, so the runtime adds no second stage.

The mirror: a tolerant re-read, not a copy

mirrorOf(state) parses puppeteer's state through AgentMonitorMirror — every level .passthrough(), so unknown fields survive verbatim. A state that fails the parse yields no mirror and the row still exists with status: unknown; the drift is logged once per run as fieldd.agents.monitor_shape_drift.

The floor's inventory and the record

The terminal row joins by runtimeSessionId; the signed record supplies the continuation claim. An inventory that stops listing a PTY is the exit backstop, given 1.5 s of grace for the floor's own session-exited to arrive with the real outcome.

One derived status, once

foldStatus folds puppeteer's open headline to idle · working · blocked · unknown. It is derived in fieldd and nowhere else — a renderer that re-derived it would be a second authority on the same fact.

Published at one frame per tick

PUBLISH_TICK_MS = 16, trailing-edge: a change is never dropped, only delayed to the next window. agent.list and agent.subscribe answer the same AgentListResult; the subscription is state transfer, never edges.

Three row kinds, one shape

The fold holds managed runs, pending runs (a live PTY this boot could not re-attach to, resumable), and exited runs whose PTY the floor still lists — the dead pane the deck is still showing, which keeps its resume verb. All three project to one AgentSessionSummary; a reader never branches on provenance.

Known defect: the desktop drops its USD readout at the renderer's fold. puppeteer's MonitorUsageState carries costUsd, costCoverage, costRatePerMin, pricedObservations, unpricedObservations and costHistory. Those fields reach the renderer intact, because the mirror is .passthrough() and upstream added them at the same schema version 3. They are then lost in packages/field-app/src/godview/monitor/useMonitorAgents.ts, whose coreUsage rebuilds the object from an explicit seven-key list of token aggregates. The function's own doc comment says every aggregate is present under its own name — true of the wire, not of this function's output. Recorded in docs/ROADMAP.md's AR row and docs/LANDED.md §AR-5-1; the fix is not scheduled. Owed

The field projection to the phone

A phone must not receive the fold. A working agent's mirror revises many times a second at 2–5 KB per row, and the desktop reads that over a loopback socket without caring. The field projection is the same board with its content removed — about 725 B per row as measured (LANDED §MF-1 corrected §5's 300–500 B estimate) — and it travels two ways from one shape. The hybrid was ruled as GM-D4: the store carries a content-free projection, and content rides the door on tap.

Carrier 1 · the door

agent.subscribe {projection: "field"} answers a snapshot then deltas, at a per-subscriber trailing-edge floor. The door is never capped: it carries the whole board.

Built

Carrier 2 · the store

AgentFieldPublisher writes this device's slice into field.agents.v1. A phone that joins the tailnet gets every desktop's board from the mesh with no fieldd in its read path. Past AGENT_FIELD_SLICE_BYTES (64 KiB, about ninety rows) the publisher drops from the end of the board order and reports omitted.

Built

What a field row carries, and what it never does

Identity, status and its clocks, liveness, the blockers' shape, two usage numbers, a context percentage, model and effort labels, the folder name, and the terminal join. Deliberately absent: lastAssistantMessage, a blocker's input/questions/detail, the title, and the mirror itself. A field row says what a run is doing, never what it said.

Two narrowings are worth naming because they are easy to undo by accident. The path never travels — only the folder's basename, because the absolute path carried the OS username and the shape of a person's disk to every node the store reaches. And each nested object is rebuilt, never spread: usage is reconstructed from exactly cumulativeTokens and burnRatePerMin, so the cost fields the desktop receives do not reach the phone at all. That second one is deliberate today and is the real subject of the unruled iOS lean D-i18, not the desktop defect above.

The consent gates on publishing

The publisher writes only while this device's product serve is active — the same door a reader dials — and it joins a row's terminal only when the floor's doors are published on the tailnet (a secret-free terminalMesh boolean on the management hello). Mesh-down is a normal state: the slice is simply not written, nothing throws, nothing logs at error, and no caller waits. Every slice carries expiresAt, so a desktop that is unplugged mid-sentence fades from every phone instead of haunting it.

The store's audience is the tailscale login. MESH_BUS_CARRIES_CONTENT is true again as of 2026-09-16, and it is a constant rather than a preference precisely because an account boundary a user can switch off is not a boundary. What makes it safe is upstream: a node built with login_allow reports only same-login peers, the hello refuses a foreign login before revealing an identity block, and a slice is applied only under its sender's authenticated device id. The gate is per node, not per store, and deliberately so: a per-store allow-list would leave the connection itself open to a foreign login for every other namespace on it. VibeField still fuses the roster against the tailnet's own peer registry — a slice may describe a device the registry lists, never add one.

History and enrollment

rosetta is the one transcript. fieldd supervises exactly one rosettad generation per user root and is its only client — readiness comes from the daemon's structured JSON line, never a scraped banner, and a daemon that keeps dying stops being restarted and says failed with a restart affordance rather than spinning. 

rosettad serve --db <user root>/index/rosetta.db \
  --addr 127.0.0.1:0 --json \
  --announce --announce-dir <user root>/index/daemons \
  --home <the OS user's home> \
  --enroll <user root>/index/enrollment.json

Four of those flags are the seam. --addr 127.0.0.1:0 and --json make the origin ephemeral and the readiness structured; --announce-dir points the daemon at a fieldd-private directory rather than rosetta's shared one; --home is the discovery scan root; and --enroll is the consent record, written before the spawn.

Consent by construction

users/<fuid>/index/enrollment.json is both VibeField's truth about what this user consented to and, byte for byte, rosettad's --enroll FILE input. One file carries both sides because rosetta ignores unknown fields at every level: the keys it reads are spelled its way, and so — for one consistent file — are the keys only VibeField reads. fieldd writes it before every spawn and restarts the daemon when it changed.

The rule that makes this tractable is ownership: a root under users/<fuid>/agents/roots/ is managed, so it is enrolled by construction; the OS user's own vendor roots are discovered by every user's rosettad and consented per user. fieldd validates every managed root the way rosetta does before writing, because a refusal at start is a non-zero exit before the daemon binds — and the supervisor would retry that into a permanent failure.

The reconcile

Every daemon ready transition re-applies the record to the personas: a managed persona the record does not name yet — created while the daemon was down, or by an earlier fieldd — is enrolled now, under the kind the roll call joins it by. The reconcile is serialized, and a change publishes and bounces the daemon once, so the ready that follows finds nothing to do.

What crosses the doors, and what never does

Never: the daemon's origin

rosettad has no authentication, so its loopback origin is the secret. It stays inside RosettadState; what reaches health is a projection of phase, reason, pid and protocol version. The announce file goes to a fieldd-private directory, never rosetta's shared one.

Never: an enrolled root's path

A persona is named by profile id. Where fieldd keeps its root is fieldd's business. A session's own working directory does ride index.sessions, as the daemon reports it.

Honest refusal over a plausible answer

A daemon that cannot answer a search says answered: false rather than returning "no matches" — an empty result and an unavailable index are different facts and a person reading a find sheet must be able to tell them apart.

The History view does not exist. It is ruled as spine content, not a plugin (AR-D9), and sits behind RO-1 — rosetta's authenticated direct data plane — as AR-8 on the roadmap. What ships today is the find sheet: search and session facts through the index.* doors, adapted to puppeteer's HistoryPort. Designed

The device domain — the one exception

Installs are OS-user-global by nature, so agent distribution is the single named exception to "all product state under the user" (AR-D15, with AR-D16 making the record root-locked). One naming caution for anyone citing the topology document: its numbered rules are R1–R7 and its decision slate is AR-D15–AR-D22. They are different series. machine/agents/distribution.json holds what VibeField actually owns there — the active executable per provider, the release-check preferences, the last update receipt — and machine/agents/updates/ holds puppeteer's opaque update transcripts. Nothing else enters machine/ without a new decision.

One writer at a time, and reads are always current (rule R6). The record is read-modify-written under the root lock every fieldd on the device shares, and published by atomic rename. An unchanged record is not rewritten. Reads re-read the file every time, so a resident fieldd's "refresh" is simply the next read and no watcher is needed. A daemon booted with no VibeField root above its user root has no machine scope at all, and the doors that would write it say so instead of inventing one.

One consequence is stated at the door rather than hidden: the active executable per provider is bound when the runtime is constructed, so agents.setActive reaches new spawns from the next boot.

Layering and the walls

Three rules in scripts/check-import-boundaries.mjs keep the sibling surface narrow, all three enforced. They run inside pnpm preflight, which proves the checker against its own synthetic fixtures (--self-test) before gating the tree (--enforce) — and preflight is the first step of pnpm verify, so a wall break stops the gate before a typecheck is attempted. They are import rules, so they bind what a plane may reach, not what it happens to use today.

The walls are wider than today's usage, and it is worth knowing by how much. fieldd imports three of its four admitted packages — puppeteer-record has no importer. field-app imports two of its four — puppeteer-monitor and puppeteer-react have none, and what it does import is puppeteer-core types plus puppeteer-views (including its /physics entry). An adapter import in fieldd would be the product branching on a provider, which is the law these rules exist to hold; native-observation is the adapters' private half and is refused on both sides.

The catalog rule

One more boundary binds the agent plane's UI. The design catalog mounts the shipping view with a fixture adapter, never a copy of its markup or CSS, and packages/field-app/test/ui-system-boundaries.test.ts enforces it — so an agent card that drifts between the catalog and the deck fails a gate rather than a review.

Sequences

Four paths worth reading end to end. Each names the doors and the files, so a maintainer can start at any arrow.

(a) Spawn — a door becomes a working agent

(b) Restart — a session outlives its daemon

A graceful stop releases, it does not close

dispose() calls the runtime's dispose({detach: true}): no exit is dispatched, no record is stamped, the claims stay allocated and the PTYs stay on the floor. Login panes are released the same way. A replacement in flight — an old PTY already terminated, its successor not yet born — is given a bounded moment to finish so a stop never leaves a person's agent dead with nothing to come back to.

The next boot's first inventory is the re-attach

Every verified, un-exited record whose PTY the floor still lists is attached at its next runtime epoch through the provider's own attach path — the bridge re-bound to the pinned port, the transcript located. A record whose PTY did not survive is stamped as an unknown exit and resumes from the door like any other.

A PTY that outlived an attach becomes a pending row

A provider that cannot attach, or a record written before this mechanism existed, leaves the run in the fold as pending: live, unobserved, resumable. The row is honest that nothing is at the wheel, which is a different claim from whether the agent is there.

Resume-when-idle replaces it on evidence

Once the index says the conversation has been still for 30 s — polled every 5 s, backing off by doubling to 60 s while the index cannot answer — the old PTY is terminated, given 5 s to leave the inventory, and the continuation is resumed into a new run in a new PTY. The new row names the PTY it replaced so the deck hands the pane over. Two processes on one native session is the one thing a resume must never make.

These are the daemon's own acts, and they are audited. A re-attach at boot and a resume-when-idle are mutations of a session a person will want to find in the ledger, so they go through the audit service's system-actor entry rather than being merely logged.

(c) Persona create — one act, three effects

agents.profiles.create

Allocates the persona's immutable root under users/<fuid>/agents/roots/<provider>/<uuid> and registers the profile in puppeteer's registry, through fieldd's injected store.

fieldd enrolls the observation root

Not the profile's dataRoot — the root the provider's own layout applies to, which differs for some providers — filed under the kind rosetta's roll call joins it by, with the profile id as VibeField's join key.

The record is published and the daemon bounces

Start-time scoping means a changed record restarts rosettad once. A persona made while the index was down is picked up by the reconcile at the next ready, so the two orders converge.

Deleting one reverses all three

Its sessions are stopped, the runtime is retired with its rows kept, the profile is unregistered, and the root is deleted with its credentials. A reconcile racing the retire must not re-enroll a persona mid-deletion, which is why the service tracks deletions explicitly. Untested under a live run — the scripted provider has no profile service. Owed

(d) Update — the vendor's own updater, under the root lock

agents.installs / agents.releases

puppeteer classifies what is installed and learns what releases exist. Both name executable paths on this machine, which is why the reads sit on the same local-only management scope as the writes.

agents.update runs the vendor's updater

An update is an attended act. Its transcript is opaque and lands under machine/agents/updates/ at 0600; a daemon with no machine scope refuses before a transcript could be opened.

The receipt is written under the root lock

Read-modify-write on distribution.json, published by atomic rename, unchanged records not rewritten. Every fieldd on the device shares that lock.

agents.setActive takes effect at the next boot

The executable map is bound when the runtime is constructed. The door's contract says so rather than implying immediacy.
