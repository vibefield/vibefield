Conventions

A VibeField door is not a function that happens to be reachable. It is a row in a registry, a zod schema, a scope, a locality class and — when it mutates — an audit record. Each of those is checked somewhere other than the handler, which is what makes the set of doors a reviewable surface rather than a growing pile.

Contracts first, and dependency-free

Every VibeField-owned wire shape is a zod schema in packages/contracts. That package has no dependencies, because it is imported from every environment — the renderer, workers and the Node daemons — and the Rust side is generated from it. Ports, scopes, stores, layout segments and environment prefixes come from registries.ts; nothing is spelled literally at a call site.

One thing the agent plane deliberately does not put in a registry is the vendors. An agent kind and a provider id are open strings with a grammar and no enumeration, because the registries belong to the siblings and are read at the seam. There is no alias table: the join between rosetta's kind and puppeteer's provider is data in the enrollment record, ruled that way when the slate was ratified.

The registry row

packages/contracts/src/methods.ts declares every method with four columns, and a registry lint rejects an unclassified method — an unregistered method does not ship.

surface

product · mgmt · mcp · push. Every agent-plane door is product.

scope

The required grant, or null for any authenticated principal. The grant lives on the connection; a missing scope is FORBIDDEN_SCOPE naming what was required.

idempotent

Whether a retry is safe by construction. It is a claim about the door's semantics, not about transport: index.enroll is idempotent because it is declarative, and agent.interrupt is not because a second interrupt acts on a run that may have moved on.

locality

local · sync · replicate · stream · federate · native-plane. Every agent-plane door is local. Erratum 2026-11-01 (PG-3b; the 3b review [11]): not since DS-2 (2026-10-01). The agent-plane doors are local, stream or federate: of the 64 in methods.ts today, 43 are local, 16 federate (a foreign device forwards the call whole to its owner) and 5 stream. Corrected 2026-11-05 (MA-1a, recounted from methods.ts): of the 69 there now, 43 are local, 19 federate and 7 stream. agent.pause (GV, 2026-11-02) federates, and MA-1a's four index.* doors add two that federate (index.apps.list, index.artifacts) and two that stream (index.apps.subscribe, index.apps.catalog.subscribe).

Locality is enforced, and it was not always. The column had no consumer from the day it was declared, so every method declared local federated in fact. Since 2026-09-13 product-api.ts reads it twice on every call: a local method is refused outright for a peer-fieldd principal whatever the tailnet preset granted, and a device parameter naming a foreign machine is refused before the forwarder is reached. The agent doors — a spawn, a resume that terminates a PTY — were the first methods declared local to walk into that gap. A peer's agent is reached by routing the call to its own device, never by federating this one.

The tolerant reader

Inbound parsing is .passthrough() with unknown-field logging. A shape that arrives with more than the contract names keeps the extra fields verbatim; a shape that arrives with less, or wrong, produces an honest degraded state rather than a blank. The monitor mirror is the sharpest case: every level of it is a passthrough, which is precisely why upstream can add cost fields at the same schema version and they reach a renderer without a contract edit.

Errors, and the honest state

Eleven kinds, each mapped to a JSON-RPC code in the server-defined range, declared once in packages/contracts/src/errors.ts: UNAUTHORIZED, FORBIDDEN_SCOPE, NOT_FOUND, CONFLICT, PRECONDITION_FAILED, UNAVAILABLE, AUDIT_UNAVAILABLE, TIMEOUT, INCOMPATIBLE, RESOURCE_EXHAUSTED and INTERNAL. Each carries a retryable flag, so a caller never has to infer one from the text.

UNAVAILABLE is the one that carries structure: {service, state, progress?, device?}. The state is a named word a UI can draw honestly rather than a sentence it must parse. The agent plane's states in the code today are no-terminal-host (the floor is not available to this daemon), session_cap, transport_not_landed (a floor serving no terminal doors — a half ticket is never minted), and the index phases the index.* doors answer from. The rule behind them: a degraded service says what it is doing, never nothing.

An upstream error code can be less honest than the one beneath it. When fieldd's host throws, puppeteer folds the throw into a flat AGENT_SESSION_CREATE_FAILED whose text is agent session creation failed: <agent>. That is one sentence for a session cap, a missing executable and an absent floor alike. So the host keeps the floor's own typed error in lastRefusal() and the door answers with that — the reason a VibeField door's error is not simply whatever the runtime handed back.
An option that cannot be honoured is refused, not ignored. agent.subscribe rejects minIntervalMs on the full projection with PRECONDITION_FAILED, because a caller that asked for a cadence and silently got the desktop's 16 ms tick would have no way to learn it had asked the wrong question.

Subscriptions

A subscription answers a snapshot on open and frames thereafter, over the same wire shape as a local subscription even when it is proxied. These rules bound them.

State transfer, never edges

The full agent subscription emits whole AgentListResult frames. A client that missed one is not wrong, only behind.

One frame per tick, trailing edge

16 ms for the fold and the usage feed, deliberately shared so a subscriber to both sees one frame of each per tick rather than two cadences. A change is never dropped, only delayed to the next window.

Revisions, and re-subscribe on a gap

The field projection's deltas apply on top of a named since. A client whose revision is not that one has lost a frame and re-subscribes for a fresh snapshot. There is no ack protocol — the tolerant reader's own rule. Since PG-1d (2026-10-31): the field and desk boards may also send a mid-stream snapshot on the same epoch, at the board's current revision: a re-present when the doors' gate flips, or the repair after a lost frame. The reader replaces its copy. Since PG-2 (2026-10-31): the field and remote boards; the desk board retired into the remote cut.

Bounded per connection

32 subscriptions per connection. A subscription is work the daemon does every tick for as long as the socket lives, so one agent.observe holder in a loop could otherwise buy the whole tick budget. Past the bound the caller gets RESOURCE_EXHAUSTED and keeps everything it already had.

Bounded in bytes, and a phone held short of the shed

A send that would take a connection's queued bytes past 128 MiB (MESH_CONTROL_LIMITS.PRODUCT_QUEUED_BYTES) closes it 1013, "client is not keeping up". A phone's subscription (the tailnet principal) whose producer can resync, today the mesh board (agent.subscribe {scope: "mesh"}), is held before that: once its connection's queue reaches 256 KiB (PRODUCT_API_LIMITS.TAILNET_QUEUED_BYTES), its deltas stop, and when the queue drains to half it is sent ONE fresh snapshot, the board as it is, never the backlog. Its own snapshots are never held, nor counted toward holding it. A peer daemon on the same door, loopback windows and every subscription without a resync keep the shed alone. Added 2026-10-31 (PG-1c, landed in 1790be95f; PG-D11 A).

Tickets, because bytes do not ride JSON-RPC

EL2 splits the planes: control-rate JSON goes through the product API, and high-rate or bulk data goes over a ticketed direct socket that the daemon is not in. A terminal's frames are the agent plane's data plane, and they go from the cell to the renderer's WebGPU terminal runtime without transiting fieldd.

terminal.openTicket and terminal.create mint TerminalOpenTicket — {route, endpoints, transportGrant, attachGrant} — for the session's own cell. Three properties are worth stating because each was once otherwise. A mint is never idempotent: every one is a fresh audited grant. A keyless or doorless cell answers UNAVAILABLE rather than a half ticket. And which endpoint shape a caller gets — loopback for a window, the tailnet shape for a WhoIs-verified self peer — is decided by its principal at mint time and by nothing on the wire. The right to type is a claim inside the grant, per client, per session, expiring and revocable by generation; the durable shared write secret that used to answer the same question was deleted rather than fenced.

native.door.* — the floor's door (mgmt)

These are not product doors. They are three verbs on the management channel, fieldd's own link to the floor, which no other caller reaches (scope null, local). field-native hosts the door, door.sock (SOCKETS.DOOR), 0600 in its 0700 run dir. The kernel names each caller: its real pid (macOS LOCAL_PEERPID, never the effective pid a delegated socket reports; Linux SO_PEERCRED), its uid, which must be the floor's own, and its start. The floor walks the caller's parents, at most NATIVE_DOOR.WALK_MAX_STEPS (32), to the first live pane's own root process that started within ROOT_BIRTH_TOLERANCE_MS (60 s) of the pane's createdAt. The bytes ride a meshdata lane of their own (protocol: "mcp", peer: "door:<connId>"), never mgmt (EL2), and the floor parses no message. A door refused at accept (refused-uid, delegated, peer-gone, limit) opened no lane, so the floor logs it and never announces it. A door outlives fieldd. The floor keeps it, accepts new ones, and holds their inbound bytes to NATIVE_DOOR's bounds (64 open, 256 KiB per door, 4 MiB in all). The next subscribe's snapshot re-announces each door, and its lane resumes. CP-1a 6b64620c … 5aa29020.

The revision rule

A row's revision bumps if and only if its projected JSON changed — never with the mirror's own revision. That single rule is what makes an idle board free: a working agent's mirror revises many times a second on usage samples and freshness stamps, and none of it reaches the mesh. The counter is a change stamp and not an ordering; it restarts at 1 when a run leaves the board and returns, so a reader applies every upsert it is given and never compares one row's revision with another's.

Login scope is a transport guarantee, and not a licence to stop thinking. The store's audience is the tailscale login: a gated node reports only same-login peers, the hello refuses a foreign login with a close code before revealing an identity block, and a slice is applied only under its sender's authenticated device id. The gate is per node, not per store — a per-store allow-list would leave the connection open to a foreign login for every other namespace riding it. VibeField still holds two rules of its own on top. No secret rides a slice — a published product endpoint is a locator and the route secret is added on forward, proved by a test that greps the published bytes. And the tailnet's own peer registry is the authority on who exists: a slice may describe a device the registry lists, never add one.

What passes, and what breaks

An added field passes

The mirror is a passthrough at every level, so a new upstream field reaches a renderer without a contract edit. The cost fields did exactly that: added at the same schema version 3 with no generation bump, and the pin gate stayed green because nothing it checks had moved.

A generation bump is caught

A bump at the pinned revision fails the pin test until the mirror is re-read against the new shape, the golden regenerated and the constant moved — the deliberate event, never a silent drift.

A rename without a bump is not caught there

The mirror is a passthrough by law, so a renamed field passes the gate. Drift in the fields fieldd actually reads surfaces at runtime as fieldd.agents.monitor_shape_drift, logged once per run, with the row surviving at status: unknown. This is a stated limit, not an oversight.

The worked example: the usage-ledger change of 2026-09-17

The change landed upstream on 2026-09-17 as a7a0c4e, "display and persist observed USD costs". VibeField took it on 2026-09-21 when the pin moved to 2f5ce002, and three breaks arrived with it — only one of them visible. A fixture tripped three type errors, which typecheck found. A stale test expectation had been red since AR-3 behind an opt-in row the ordinary gate never runs. The third was silent: upstream's export changed to hand the store only the conversation's live run, which upstream's own host answers with a per-run merge that preserves corrections by revision — while VibeField's renderer-local cache still replaced the whole record. Nothing in the type system could see it, and the symptom would have been a resumed conversation quietly losing every earlier run's observed spend. The generation was correctly left alone throughout: the changed types are the views package's, which this number does not cover.

The lesson the pin gate cannot teach. A clean typecheck across a pin move says the shapes still line up. It says nothing about a rule that is mirrored on both sides of the seam, where upstream changing its half silently desynchronises yours. A change can type-check, keep its generation legitimately, and still mean something else. Recorded in docs/LANDED.md §AR-5-1; the cache now merges by run id with revision precedence and writes a versioned document so a pre-USD record is dropped on read rather than shown as dollars.
